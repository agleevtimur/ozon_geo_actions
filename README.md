# Ozon Actions Geo Updater (Telegram Bot)

**Назначение**: менять географию (поле `addresses`) в *уже существующих* акциях Ozon,
на основании фактических остатков по кластерам/регионам. Бот **ничего кроме географии не меняет**:
заголовок, даты, тип и т.д. сохраняются, берутся из текущих параметров акции через `view`-эндпоинт.

## Быстрый старт (Railway)
1. Залить репозиторий.
2. Указать переменные окружения:
   - `TELEGRAM_BOT_TOKEN` — токен бота.
   - `OZON_COOKIE_PLAIN` — *plain text* Cookie (как в браузере, без path/expire).
   - `OZON_COMPANY_ID` — ID компании (например `1297124`).
   - `ACTIONS_IDS` — список ID акций через запятую (например: `2983461,2983456,...`).
   - *(опц.)* `GEO_JSON_BASE64` — base64 от сырого geo-JSON с полями `type` = country/region/city и `uid`.
3. Запустить воркер (бот). Команда запуска: `python -m app.bot`

## Команда бота
- `/update_geo` — обновить географию **для всех** акций из `ACTIONS_IDS`.
- `/update_geo <id>` — обновить географию только для указанной акции.

## Как это работает
1. Бот получает список SKU для акции (через `OzonClient.list_action_skus`) и достает остатки по кластерам.
2. `stocks.aggregate_by_cluster(raw)` агрегирует по кластерам → регионам.
3. На основе регионов формируются `addresses` (UID региона + всех его городов).
4. Текущие параметры акции запрашиваются через `view`; география заменяется и отправляется `update`.

⚠️ Если `view`-эндпоинт недоступен/меняется, используется **fallback**: тело запроса собирается
по образцу UI с неизменяемыми полями из статики (можно переопределить через ENV).

## Настройка соответствий
- `app/geo_mapping.py` ожидает **сырой** JSON с иерархией country > region > city, у каждого объекта есть `uid`.
  Можно передать через `GEO_JSON_BASE64` или положить файл `data/geo.json`.
- Кластера → регионы настраиваются в `app/stocks.py` (функция `aggregate_by_cluster`).
  Эта реализация повторяет **старую** логику (см. комментарии и места для адаптации ключей под ваш API).

## Точки интеграции под ваш бэкенд
- `OzonClient.fetch_stocks_raw_for_skus(skus)` — верните *сырой ответ* вашего старого эндпоинта остатков.
- `stocks.aggregate_by_cluster(raw)` — уже принимает "сырые" данные и собирает структуру по кластерам/регионам.
- `OzonClient.list_action_skus(action_id)` — верните SKU, участвующие в акции (если для остатков это требуется).
  Если ваш сервис остатков не фильтруется по SKU, можете вернуть пустой список — агрегация всё равно сработает.

## Запуск локально

python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
